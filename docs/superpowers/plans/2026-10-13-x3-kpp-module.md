# X3 KpP Module Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking. No delegation is requested in this task.

**Goal:** Реализовать в существующем X3 связанный рабочий путь КпП по нескольким ПБО,
с планами действий, задачами, назначенными проверками и состояниями процесса.

**Architecture:** Независимое приложение `variants/enterprise-audit/` сохраняет
свой ID/ключ. Отдельные domain/repository/UI модули расширяют существующий аудит.
Repository асинхронно исполняет локальные команды и предоставляет заменяемый
контракт; это не работающая серверная интеграция.

**Tech Stack:** HTML, CSS, JavaScript UMD; Node built-in test runner;
собственные существующие библиотеки PDF и шрифт X3; браузерная проверка через IAB.

**Spec:** `docs/superpowers/specs/2026-10-13-x3-kpp-module-design.md`.

## Global Constraints

- Только `variants/enterprise-audit/`; не менять X1/X2/архивные варианты.
- Только ключ `pusk:enterprise-audit:v1`; сохранить существующие ответы.
- 48 исходных вопросов не менять; частичный визит использует подмножество ID.
- Все производственные неизвестные и действия других участников явно демонстрационные.
- Не назначать КпП неподтверждённые права и не вводить производственную формулу.
- Не коммитить, не пушить и не публиковать в этой работе автоматически.

## Review Focus

1. Старое состояние без workspace: расширение не теряет визиты/фото/позицию.
2. Повтор команды/старый revision: нет второго решения и ложного успеха.
3. Возврат с вложенной страницы: восстанавливаются ПБО, фильтр, задача и черновик.
4. Частичный повторный: только назначенные вопросы входят в прогресс/PDF/проверку.
5. Открытый отчёт/согласованный ПД: не закрывают автоматически ознакомление/исполнение.

## Структура файлов

- `js/workspace-domain.js`: сущности, миграция, селекторы, команды и переходы.
- `js/workspace-repository.js`: асинхронное чтение/запись, revision/idempotency,
  ошибка/конфликт, мост к прежнему сохранённому состоянию.
- `js/workspace-ui.js`: главная, портфель, задачи, ПД, действия, программа, процесс,
  аналитика, панель демонстрации передачи работы.
- `js/workspace-seed.js`: явно обозначенный локальный набор сценариев.
- `css/workspace.css`: собственные адаптивные стили новых экранов.
- `js/app.js`: мост к модулю и назначенному составу аудита; текущие сохранения/PDF.
- `js/report-pdf.js`: расширение реквизитов назначенного визита; документ плана.
- `index.html`: собственные модули, меню/название; оболочка не получает бизнес-логику.
- `tests/workspace-domain.test.cjs`, `tests/workspace-repository.test.cjs`,
  `tests/workspace-integration.test.cjs`: смысловые переходы/сохранность данных.
- `README.md`, `design-qa.md`, `docs/prototype-architecture.md`: фактический итог.

## Task 1: модель, миграция и переходы

**Interfaces:** Produces `createWorkspace({sites, today})`,
`migrateWorkspace(workspace, {sites, today})`,
`applyCommand(workspace, command, {actor, now})`,
`selectQueue(workspace, visits, {siteId, status, query})`,
`selectPlan(workspace, planId)`, `selectProgram(workspace, siteId)`.
Команды возвращают `{workspace, result}`; недопустимые переходы выбрасывают
типизированную ошибку `code` без изменения исходного объекта.

## Task 4: назначенные визиты, частичный повторный и ИПУР

**Interfaces:** `startAssignment(assignmentId)` создаёт или открывает тот же
визит с `assignmentId`, `questionIds`, `scopeLabel`. Завершение сообщает repository
командой `complete_assignment` с visitId и итогом. Результат назначения не вычисляет
другие процессы сам по себе; переходы выполняет модель демонстрационного процесса.

План реализован в существующем X3. 50 тестов, включая 18 прежних, проходят.
Независимое ревью: три Important, воспроизводящие RED→GREEN проверки; исправлены.

ветки проверены тестами модели, а не ручной имитацией ошибок браузера.
Работа выполнена локально; commit/push/публикация не выполнялись.
Неподдерживаемое инструментом скачивание blob из iframe не считается проверенным;
реальные PDF-планы и сохранность состава старой версии проверены генерацией/извлечением.
