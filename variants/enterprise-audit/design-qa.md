## Основание и сравнение

Пользователь выбрал второй макет и приложил его повторно. Источник:
../../output/design-x3/concept-2-enterprise.png, 853 × 1844. Нормализация до
390 × 844 CSS px; приложение в iframe измерено как 390 × 844, nav 390 × 70,
верх nav = 774. Отдельный статический вариант выбран по обязательной архитектуре
проекта; общий mobile-app template не заменяет независимые приложения.

Сравнение выполнено в едином изображении, а не из памяти или только из кода:
../../output/design-x3/comparison-x3.png — первый проход;
../../output/design-x3/comparison-x3-type.png — увеличенные шрифты/карточка;
../../output/design-x3/comparison-x3-regions.png — после исправлений.

Особенность захвата in-app браузера: после перезапуска его API viewport менял
геометрию DOM до 390 × 844, но фактический screenshot обрезал высоту до 780 px;
fullPage/clip > native viewport не поддержались. Поэтому основной контент
сравнен равными областями при CSS viewport 390 × 844, а нижняя навигация —
отдельными равными 390 × 70 областями (реальный screenshot x3-nav.png при
390 × 740). Сводное изображение — явно обозначенный монтаж областей для QA,
не выдаётся за единый screenshot приложения. Масштаб областей не растянут.
Исходный полный макет, полный первый capture и все сравниваемые области открыты.

Состояние: выбран ПБО 29779, новый визит, пример предыдущего визита. Для
финального сравнения дата 14 вместо 13 октября: на 13 октября уже был локальный
черновик 1/48, который сохранён. Дата не меняет размеры/переносы; динамическое
состояние «Продолжить» отдельно проверено. Пример истории явно маркирован
демонстрационным, чтобы не выдавать нарисованный прошлый визит за реальные данные.

## Поверхности визуальной проверки

- Шрифты: локальный Inter variable, fallback Arial; 32 px/800 заголовок, 31 px
  предприятие, 22 px подзаголовки; акценты и уровни сохранены. Имя, описания и
  реальные длинные вопросы переносятся без обрезания. Source mock имеет немного
  другой оптический вес; небольшая разница classified P3, читабельность сохранена.
- Отступы/форма: одинаковый порядок, поля 20 px, карточка ПБО с выносом 5 px,
  радиусы 8–12 px, кнопка старта 50 px. Последний визит остаётся в прокрутке
  на меньшей высоте; нижняя навигация закреплена и доступна.
- Цвета: тёмный зелёный #20543d, чернильный #071b18, sage #edf2e8, wash #f6f8f5,
  оранжевый для уведомления, красный для критических ответов. Плоская зелёная
  кнопка слегка отличается от градиентного raster mock (P3), состояние понятно.
- Assets: стандартные Phosphor regular 2.1.1, MIT; без самодельных SVG/emoji.
  Выбранный экран не требует иллюстраций/аватаров. Иконки резкие и одной семьи;
  небольшая разница формы swap/активной вкладки относится к P3. Домашний индикатор
  из нарисованного референса не превращён в UI-элемент.
- Текст: ПБО, дата, число вопросов, условия и история понятны отдельно от чата.
  «Демонстрационный визит» и замечание о локальных метриках — сознательные
  уточнения источника данных; внутренние названия вариантов вынесены в меню.

## Адаптивность, состояния и доступность

Проверены CSS ширины 320, 390, 768 и 1280. На 320 clientWidth == scrollWidth;
на tablet/desktop контент ограничен 560 px, длинное название переносится.
Evidence: x3-mobile-320.png, x3-tablet-768.png (открытый picker),
x3-desktop-1280.png (длинное имя). Native capture высоких состояний ограничен
780 px, что явно учтено; отсутствие горизонтального переполнения проверено DOM.
Меньшая высота вызывает вертикальную прокрутку, не скрывает постоянные controls.

Проверены выбранный ПБО, пустой поиск, календарь, открытое/закрытое меню,
модальные панели, focus ring и клавиатурный chooser. Семантические кнопки,
radio groups с вопросом в label, textbox с подписью, native details/summary.
Модальные panels trap Tab; screen/tabs inert. MutationObserver возвращает inert
при закрытии меню оболочкой, не вмешиваясь в ответы. Анимаций нет.
Физические устройства, системное масштабирование текста и полная screen-reader
сессия не тестировались, поэтому универсальная accessibility conformance не заявлена.

→ предварительный PDF → подтверждение → PDF → возврат → завершённый результат.

- 48 исходных вопросов идентичны источнику SHA-256; формулировки/ID/options не менялись.
- Ответ «Нет», причина и комментарий восстановились после reload.
- «Без ответа» показал 47 вопросов, до заполнения завершение/PDF disabled.
- Ответы не вызывают автоматического перехода; причина/комментарий остаются доступны.
- 46 Да / 48 = 95,8%; один критический Нет дал неудовлетворительный результат.
  В проверке доступны отдельные проценты и реквизиты с исходными ролями Test Hub.
- Назад из проверки → заполнение. Нужный ответ редактируется по прямой кнопке.
- Предварительный PDF до завершения: шесть реальных страниц, 48 ответов, маркировка,
  причина, комментарий и роли проверены в экспортированном файле через pypdf.
- PDF.js отрисовал шесть canvas; настоящий документ просмотрен визуально.
- Из подтверждения PDF вернулся в ту же панель с выбранным «Да» фальсификации.
- Финал readonly, кнопок изменения нет. Задача результата открыла этот же визит.
- Финальный файл повторно экспортирован после исправления фото: шесть страниц,
  48 ответов, 1 изображение, «Факт фальсификации: Да», завершённый статус,
  без предварительного заголовка. Evidence: x3-preliminary.pdf, x3-final.pdf.
- История/задачи, В работе/Завершены, поиск другого ПБО, фильтр периода и пустое
  состояние проверены UI. Пример исключён из локальных метрик/задач.
- X1/X2 загружены по прежним путям. Все три варианта показаны в shell menu.
  Источник X1 и все копируемые файлы X2 после работы совпали с контрольными суммами.
  Сброс по коду удаляет только свой стабильный ключ; на пользовательском черновике
  destructive reset не запускался. Переноса состояния нет.

Независимое code review: замечание по keyboard photo исправлено и перепроверено;
других P1/P2 reviewer не нашёл. Браузерных console error/warn в проверке не было.
