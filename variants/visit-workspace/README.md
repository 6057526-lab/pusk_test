# X3 — удобное внесение

ID: `visit-workspace`. Создан 2026-09-23 из `variants/product-proposal/`.
Точный снимок исходных файлов: `source-sha256.json`. Код и стили скопированы;
живых зависимостей на X1, текущую мобильную копию или X2 нет.

Цель по запросу пользователя: предложить свой вариант удобного внесения ответов.
Это UX-гипотеза команды, а не решение, уже проверенное менеджерами.

## Изменения и сценарий

- Главная с метриками ПБО и бургер-меню ведёт через «Внесение визитов» к списку
  чек-листов и реквизитам. После создания визита, ознакомления с политиками и
  завершения опроса используются экраны задач, как в общем бизнес-сценарии.
- Дополнительный экран «Мой визит» доступен из меню: продолжение черновика,
  обзор заполнения, результаты и удаление локального визита.
- Те же 48 вопросов, разбитые на 15 блоков до четырёх вопросов. Границы исходных
  смысловых разделов сохранены. Можно идти последовательно или выбрать блок.
- Причины открываются у ответа «Нет», комментарий раскрывается по необходимости.
- Пропуски доступны из обзора и проверки; нет автозаполнения ответов.
- Черновик, причины, комментарии, локальные фото, реквизиты, номер блока и
  завершённый результат сохраняются в localStorage под ключом
  `pusk:visit-workspace:v1`. При ошибке записи показано предупреждение.
- Перезагрузка открывает карточку визита; «Продолжить» возвращает в прежний блок.
- Обзор → проверка ответов → подтверждение фальсификации → результаты.
- Удаление визита в X3 требует подтверждения и удаляет только его ключ.
  «Начать заново» в DEV также удаляет только черновик X3 после подтверждения.

Запуск: `../../demo/index.html` → «X3 · Удобное внесение», либо свой `index.html`.
Главная → меню → Внесение визитов → чек-лист → ПБО и дата → задача ознакомления
→ политики → задача заполнения → разделы → блоки вопросов → проверка
→ подтверждение → задача результатов → отчёт → экран документа.
Экран документа имитирует PDF в HTML; скачиваемый PDF пока не создаётся.

## Ограничения

Поддерживается один локальный визит. Это сохранение в данном браузере, не на сервере;
очистка данных браузера удалит визит. Одновременная работа в нескольких вкладках
не синхронизируется: последняя запись побеждает. Большое фото может превысить квоту;
в таком случае интерфейс сообщает, что нельзя закрывать вкладку.
Нет проверки на физических устройствах/Safari и исследований с менеджерами.
Нераскрытые в источнике сведения, политики, другие чек-листы, расчёт оценок
и настоящий PDF остаются ограничениями базы. Отчёт — HTML-представление ответов.
Старые служебные ветки меню унаследованы, основной эксперимент — внесение аудита.

## Проверка

Chromium: полный путь от главной и меню до экрана документа, 15 блоков/48 вопросов, запись и восстановление
ответов, причин, комментария и позиции после перезагрузки, переход к пропускам,
завершение и восстановление отчёта, удаление визита. Отдельно — запуск четырёх
вариантов, изоляция состояния, ширины 334/390/406 и отсутствие перекрытия футером.
Сценарии Playwright CLI: `qa.js`, `qa-shell.js`; скриншоты в `../../output/playwright/`.
