## Текущий сценарий после встречи 14.10.2026

- Главная с IPUR по ПБО, незавершёнными визитами и CTA «Внести / Продолжить визит».
  IPUR и закрепление ПБО — данные примера; количество визитов — локальные записи.
- Нижнее меню «Главное — Визиты — Задачи»; бургер — дополнительные переходы.
- Визиты: выбор чек-листа → дата → ПБО (один экран реквизитов) → начало →
  ознакомление и согласие → заполнение внутри разделов → проверка/PDF →
  подтверждение завершения → результат только для просмотра.
- Два чек-листа: «Аудит безопасности пищи» — 48 исходных вопросов;
  «Практика работы с людьми» — пять демонстрационных вопросов из переданного
  прототипа основного проекта (`STRUCTURES.people2026`, `js/data.js`).
  Пользователь подтвердил достаточность этого набора для демо. Полный опросник
  не найден ни в первом, ни во втором пакете передачи; новые вопросы не придуманы.
- Критические вопросы первыми; идентификаторы и исходные индексы сохранены.
  Назначенный частичный повторный сохраняет свои 13 вопросов гигиены.
- После ответа: вручную, схлопнуть карточку или прокрутить к следующей.
  Схлопнутый ответ можно открыть для комментария/фото; фильтр «Без ответа» сохранён.
- Предварительный результат над ответами: ниже 80% подсвечивается после ответа
  на все некритические вопросы. Это демонстрационный порог; веса не подключены.
- Фальсификация запрашивается только в практике работы с людьми. В пищевом
  аудите нет этого поля в форме, подтверждении, результате и PDF.
- Настоящий предварительный PDF сохраняет возможность редактирования.
  После явного подтверждения ответов редактировать нельзя. Черновики и фото
  сохраняются под прежним ключом X4; перенос из X3 отсутствует.
- Расширенные механики ПД/программы/межролевого примера сохранены как исторический
  эксперимент в этой копии. Главное меню текущего сценария к ним не ведёт.
  Старые подготовки и ответы не удаляются; каталог основной формы показывает два типа.

## Ограничения

Фронтенд для согласования с бизнесом. Backend, SSO, рабочие права, опубликованные
версии/группы прохождения и реальные назначения не подключены. Формула итога:
доля «Да»; ниже 80%, критический «Нет» или фальсификация «Да» в практике работы с людьми
дают неудовлетворительный результат. Ровно 80% и выше — удовлетворительно при
отсутствии других причин отказа. Граница подтверждена пользователем для этой
демонстрации; производственные веса не подключены.
Пищевые сравнения исторической аналитики исключают другие чек-листы.
ИПУР использует пищевой состав примера. Детали: `design-qa.md`, `backend-contract.md`.

Выкладка 365ec01 откачена по запросу пользователя. X4 добавлен локально и в ветку.
Railway сохраняет прежнюю версию; это разделение не запускает повторную публикацию.

## Упрощение представления X4 — 14.10.2026

Главная: информационные метрики без кликов и списка предприятий.
Каталог «Внесение визитов» использует заголовок исходника и две карточки без
дополнительных пояснений. В реквизитах нет кнопки «Сменить чек-лист»;
назад возвращает в каталог. Дата/ПБО/старт сохранены.
Шапка раздела и кнопка «Разделы» закреплены под прогрессом. Убраны подпись
сохранения и настройка после ответа из анкеты; настройка перенесена в меню
X4 над выбором вариантов. Критическая карточка имеет один подчёркнутый
заголовок «Критический вопрос» и жирный текст; обычные вопросы — обычный текст.
Незаполненная анкета остаётся на форме при проверке с ошибкой и переходом
к пропускам. Старый сохранённый незаполненный экран проверки возвращается
в форму без удаления ответов. Допустимые «Неактуально» считаются отвеченными.

## Причины ответов и подтверждение — 14.10.2026

После «Нет» причина обязательна: исходные варианты конкретного вопроса,
либо свободный текст в комментарии. Для «Другое» — уточнение в том же комментарии.
Фото необязательно. Готовые причины и комментарий выводятся в результат/PDF.
Старые отдельные причины объединяются с комментарием без потери введённого текста.
Предварительная проверка/PDF и завершение не проходят без причин, завершённые
исторические записи остаются для просмотра. ПБО выбирается через карточку,
без отдельной кнопки «Сменить ПБО». В подтверждении ПБО, дата, чек-лист и итог;
повторного PDF нет. Источник готовых вариантов — why в неизменённом questions.js.

## Задачи по смыслу X1 — 14.10.2026

Единая лента вместо блоков черновиков и назначенных проверок расширенного примера.
Действия и исходные примеры — из TASKS prototype/js/app.js. На карточке чек-лист,
ПБО (если передан), автор и дата. Фильтр «Все / Чек-листы / Результаты» с числами.
Три входящих примера обозначены; пищевой открывает согласие → анкету. Его задача
превращается в продолжение того же визита, сохраняя исходные автора/дату.
Управление предприятием и поддерживающие визиты пока открывают только реквизиты:
их полные опросники не подключены, пищевые вопросы вместо них не используются.
Задачи результатов — только открытые ознакомления текущего КпП по реальным
локальным записям. После ознакомления задача исчезает из очереди, результат остаётся.
Статичная запись результатов практики X1 не превращена в новый фиктивный визит.
Создание обычного визита по-прежнему проходит напрямую через условия к вопросам.
